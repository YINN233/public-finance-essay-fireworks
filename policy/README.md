# 政策文本采集手册

**目的**：把 `policy.csv` 填到能跑 DiD 的程度。这是目前唯一卡住分析进度的环节——数据和脚本都已就绪。

**时间预算**：38 城 × 约 15 分钟 = 约 10 人时，五人分工约 2 小时（每人 8 城）。

---

## 一、字段怎么填

一行 = **一次政策变动**（不是一年一行）。同一城市若有多次修订，就写多行；`merge_policy.py` 会自动把它们展开成"城市 × 日"的政策状态。

| 字段 | 填什么 | 示例 |
|---|---|---|
| `city_code` | 地级行政区划代码（6 位） | `210600` |
| `city_name` | **用空气质量数据里的名字**（地区行署城市用地区名） | `阿克苏地区`、`丹东` |
| `province` | 省/自治区/直辖市 | `辽宁` |
| `effective_date` | **生效日期**，`YYYY-MM-DD`。这是最关键的字段 | `2013-12-09` |
| `policy_type` | 见下方判定规则（1/2/3） | `3` |
| `scope` | 禁放/限放覆盖范围 | `中心城区7区`、`全市` |
| `restricted_days` | 允许（或禁止）燃放的日子 | `除夕至正月十六` |
| `restricted_hours` | 允许（或禁止）燃放的时段 | `除夕7:00至初一1:00` |
| `designated_sites` | 是否设集中燃放点及数量 | `是，12处` |
| `penalty` | 罚则 | `罚款500元`、`可拘留` |
| `sales_ban` | 是否全年禁售 | `是` / `否` |
| `tax_instrument` | 是否存在价格型工具（判定规则见第二节末） | `0` / `1` / `2`；空 = 待核实，**不要默认填 0** |
| `issuing_agency` | **发文主体**（政策动机的代理变量，必填） | `市公安局`、`市应急管理局` |
| `source_url` | 一手文件链接 | 政府网站链接 |
| `verified` | `Y` = 已看到文件原文；`N` = 仅据新闻转载 | `Y` |

## 二、policy_type 判定规则（最容易出错，务必按此执行）

看通告里**有没有"允许燃放时间"这一条**：

| 值 | 判定 | 判别特征 |
|---|---|---|
| **3** | **全面禁放** | 声明"全年禁止燃放"、"禁止燃放烟花爆竹"，**没有**任何允许燃放时段。春节也在禁放范围内 |
| **2** | **限放** | 明确写出允许燃放的时段（如"除夕至正月初一全天、正月初二至十五 8:00—24:00"）或允许燃放的区域。**春节是许可窗口** |
| **1** | **无专门管制** | 无市级燃放管理规定，或仅有一般性场所禁放（加油站、医院、学校等任何城市都有的条款） |

> ⚠️ 关键区分：**"限放"不是"较弱版本的禁放"，而是另一种制度**（春节允许燃放）。把它当成 3 会直接毁掉处理变量的含义。
> ⚠️ 只列"几类场所禁止燃放"（加油站、文物保护单位等）**不算** 3，也不算 2——那是所有城市都有的常规条款，应记为 1 或沿袭前一状态。

### 另一个容易误判的字段：tax_instrument

这个字段用来检验文章第二块机制的前提——**"现实中几乎没有城市用价格工具管燃放"**。这是一条**断言**，必须由政策库支持或推翻。

| 值 | 含义 |
|---|---|
| `0` | 已查，**没有**地方价格型工具（只有禁放／限放这类命令控制） |
| `1` | **有地方（省／市／县）层面的价格型工具** |
| `2` | **有国家层面的消费税覆盖**（对所有城市无差别，只作为背景记一次） |
| 空 | 待核实 |

**判定规则，按重要性排序：**

1. **罚款不算价格型工具。** 罚款是违规被查处后的处罚，它惩罚的是"被抓住"，不是"产生外部性"，也不改变一单位**合法**燃放的边际成本。**这是最容易误判的一条**——把罚则记成 `1` 会让整个前提失真。
2. **销售环节的税费算。** 批发或零售环节征收的税费、专卖加价、特许经营费、零售许可拍卖，都属于 `1`。
3. **对燃放行为直接收费也算。** 燃放许可收费、集中燃放点收费、押金退还制，都属于 `1`。
4. **记 `1` 时必须在 `revision_note` 写清形式、税率与征收环节。**
5. **国家消费税与地方工具分开记。** 若烟花爆竹在国家消费税税目内，那是全国统一、且征收在生产端，不能解释城市间差异——按 `2` 记一次即可，不要逐城重复。
6. ⚠️ **待核实**：烟花爆竹目前**是否仍在国家消费税税目内**、税率多少、在哪个环节征收。这一条会影响文章第二块机制的措辞——如果存在一个名义上的消费税，那么准确的说法不是"没有税"，而是"**有一个名义上的税，但它不反映边际损害，所以现实中仍以禁放为主要工具**"。后者其实是更好的问题。

### 两条格式硬规则

1. **字段内若含逗号，必须用双引号把整个字段括起来**；更稳妥的做法是用顿号「、」代替字段内的半角逗号。
2. **否则整行会静默错位，而且不会报错**——示例文件里就犯过这个错：3 行错位，把政府网站的 URL 读成了"发文主体"，而发文主体是政策动机的核心变量。现在 `merge_policy.py` 会逐行做字段数校验并报警告，填完务必运行一次看有没有 `!!`。

## 三、去哪里找

**顺序**：市政府官网 → 市公安局 → 市应急管理局 → 市人大法规库 → 地方新闻（仅用于交叉核对日期）。

**检索式**（把关键词直接粘进搜索引擎或站内搜索）：

```
<市名> 烟花爆竹 燃放 通告 site:gov.cn
<市名> 禁止燃放烟花爆竹 规定 全文
<市名> 烟花爆竹 限放 实施方案
<市名> 烟花爆竹 燃放管理规定 修订 废止
```

**必查的三件事**：① 起始年份（该市**第一次**出台禁放或限放规定是哪年）；② 是否发生过"禁→限"或"限→禁"的切换及日期；③ 现行有效版本（有的旧通告页面标注"已废止"）。

**交叉核对**：同一政策至少两个来源（政府网站 + 新闻），日期不一致时以政府网站为准。

## 四、质量标准

- `verified=Y` 的门槛：**亲眼看到政府网站或人大法规库上的文件原文**（能打开、能看到发布日期与生效条款）。仅看到新闻转述的，一律记 N。
- 日期宁可空着也不猜。**不确定的字段留空 + 在 `revision_note` 里写清疑点**，比填一个错日期有害得多——错日期会污染整个 DiD。
- 每次填完一批，运行 `python3 -I scripts/merge_policy.py` 看覆盖率报告。

## 六、第二阶段：变异在哪，先想清楚

**这一步很关键，别跳过。** 2015–2022 年那波"全面禁放"主要发生在**普通地级市**，不是省会——因为省会多为"限放"，而 2023 年之后被法工委点名要求修改的，也集中在这些普通地级市的"一刀切"禁令上。**所以政策变异的主体不在上面这 38 个城市里。**

因此第二阶段要做两件事：

1. **先找名单，再逐城核**：检索"全面禁放烟花爆竹 城市 名单"、"禁放 一刀切 整改 城市"，以及全国人大常委会法工委 2023 年备案审查工作情况报告中提到的具体案例，据此锁定哪些城市有过全面禁放、哪些在 2023–2025 年改成了限放。**先拿到名单，变异就定位了。**
2. **扩到全国地级市**（约 300 个）。数据侧不需要重跑——`panel_cityday.csv` 已含 389 个城市，缺的只是政策文本。

## 七、填完之后

```bash
python3 -I scripts/merge_policy.py          # 合并政策变量，输出覆盖率与分组均值
```

脚本会打印"政策类型 × 相对日"的均值表。**如果 3（全面禁放）那一组的样本不足 20 城，说明第二阶段的名单还没找齐**，此时不要急着跑回归。
